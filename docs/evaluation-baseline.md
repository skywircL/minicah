# 金种子真实模型开发基线

本流程使用已校准的 `gold-seeds-v2`，当前数据版本 2.3.2。基线用于观察模型在真实工具链中的任务成功率；参考校准、H/P 工程检查、人工金种子验收各自保留独立状态。

## 运行前检查

```sh
node scripts/evaluation/gold-baseline.mjs --plan
node --test scripts/evaluation/gold-baseline.test.mjs
```

`--plan` 只检查配置、数据/运行时指纹及校准证据，不请求模型 API。默认沿用启动目录 `.env` 或环境中的 `DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_API_KEY`。密钥不会写入计划或报告。当前配置为 `deepseek-flash`、`https://api.deepseek.com`、thinking 关闭、单次输出上限 4096 tokens。

执行计划包含 14 条 A 轨道任务：12 条单轮任务共 44 次，2 条多轮任务共 10 次，总计 54 次独立试验。普通任务重复 3 次，高风险任务重复 7 次；并发为 1。A5 每次试验保持同一个 Runtime/Session，完整两个轮次算一次试验。每次重复重建工作区及会话。

外部服务可见材料包括公开给候选模型的题面、测试工作区内的文件、系统提示、工具定义、工作区路径，以及模型生成内容和工具结果。隐藏判分器、期望结果、参考解、反例、人审台账、来源快照和工作区外项目源码留在本地。v2.3.2 的输入清单位于 [payload-review.md](../.minicah/gold-baseline-preflight/v2.3.2/payload-review.md)，同目录保存执行计划和用户出站授权。父目录的同名清单属于 v2.3.1 历史输入；下一轮运行前仍应按相应版本核对。

## 执行和结果

```sh
node scripts/evaluation/gold-baseline.mjs
```

执行需要模型 API 网络访问和 macOS 原生沙箱权限。函数判分走已有受信任沙箱服务，候选模型无法请求 shell 命令；文件写入只发生在试验工作区。`Ctrl-C` 取消后等待清理；基础设施错误或未确认清理会停止后续模型试验。

报告写入 `.minicah/gold-baselines/baseline-*/`：

- `plan.json`：数据/运行时/驱动 hash、逐条种子 hash、模型配置、重复次数及引用的工程校准证据。
- `driver.mjs`：本次运行使用的驱动源码副本，仅用于审计；重新执行应使用项目中的脚本。
- `report.json`：逐次分类、通过/失败/排除、失败判据、用量、源报告和日志 hash。
- `report.md`：按种子汇总的开发基线。
- `evaluation-*/`：单轮执行的原始报告和 Session 日志。
- `GS-A5-*/`：同会话多轮执行、最终工作区和 Session 日志。

必需判据明确失败且清理确认时计入失败，即使另一判据证据不足；加权分数仍可为 null。提供方错误、取消、未知副作用、缺失证据及未运行条目不得冒充模型成功。用量只合计提供方实际返回的 token，并单列缺失次数；不估造账单。运行结束重新核对全部指纹，变化则标记 stale。

`--repetitions N` 可显式覆盖次数用于小型诊断，覆盖值记录在计划中。未按 3/7 次协议运行的结果不得冒充完整重复基线。

## 结果边界

数据目前属于已公开审阅的 `gold_dev`，不构成未见留出集。A5-02 使用固定压缩文本，评测的是压缩后任务接续，不是模型自动摘要质量。24 条 H/P 契约引用已有校准，不能加入模型能力通过率的分母。人工台账仍为 pending 时，基线可以用于开发诊断，但不能把它改成 acceptedGold 或发布批准。

运行脚本和本说明位于金种子已有 hash 依赖之外；新增基线工具不会改动已校准题目。每份基线独立绑定自己的驱动 hash，同时引用原金种子 manifest/runtime hash。

## 首轮结果（2026-10-03）

已完成 v2.3.1 / deepseek-flash 的 54 次协议试验：22 次通过、32 次失败、0 次排除；按种子宏平均 pass@1 为 44.2%，按试验计通过率为 40.7%。已有 Outcome、Behavior 判据在 54 次中均通过；32 次失败全部来自 Response。单轮及多轮任务合计产生 42 个回复格式失败：39 个包含正确的 JSON 对象但附加了说明或围栏，另外 3 个使用了未加双引号的 status 键。以上诊断不改变原始分数。

运行用时约 210 秒；209 次模型请求均返回用量，合计 319,853 tokens。当时核验 65 个报告/日志证据文件后，数据、运行时和驱动指纹匹配。当前提示及数据已升级到 v2.3.2，旧报告绑定的 v2.3.1 数据位于金种子 archive/v2.3.1，不能把旧成绩当作当前版本成绩。结果保存于：

- [正式基线汇总](../.minicah/gold-baselines/baseline-dJPDnJ/report.md)
- [失败归因和样例](../.minicah/gold-baselines/baseline-dJPDnJ/analysis.md)

重新生成本地分析（不调用模型 API；当前数据不同则读取按报告版本归档的数据，并严格验证逐条 hash；当前指纹不匹配是版本变化，不会重算历史成绩）：

## v2.3.2：先统一要求

已将系统提示改为优先遵从用户指定格式，并将全部 16 个公开任务轮次统一为合法 JSON 示例与仅 JSON 回复要求。业务期望、评分、参考解和反例保持不变；没有对旧回复做正文剥离或追认通过。版本变更、对照检查和校准方式见 [金种子说明](evaluation-gold-seeds.md)。

统一要求阶段只做本地测试、参考校准和审计。用户随后确认验收完成，并明确授权将新版公开载荷发送至官方 DeepSeek API；由此运行以下独立真实模型对照。

## v2.3.2 对照结果（2026-10-03）

沿用 `deepseek-flash`、thinking 关闭、输出上限 4096 tokens、并发 1，以及普通题 3 次/高风险题 7 次协议，完成 54 次试验：**54 通过、0 失败、0 排除**。所有试验清理确认，提供方错误为 0，数据、运行时及执行驱动指纹匹配。

| 指标 | v2.3.1 | v2.3.2 |
| --- | ---: | ---: |
| 通过 / 可计分试验 | 22 / 54 | 54 / 54 |
| 种子宏平均 pass@1 | 44.2% | 100% |
| 按试验通过率 | 40.7% | 100% |
| Outcome 通过 | 54 / 54 | 54 / 54 |
| Behavior 通过 | 54 / 54 | 54 / 54 |
| Response 通过 | 22 / 54 | 54 / 54 |
| INVALID_JSON 回复轮次 | 42 | 0 |
| 模型请求 | 209 | 195 |
| 已观察 token | 319,853 | 308,919 |

宏平均 pass@1 增加 55.8 个百分点；原格式失败在本轮未再出现。既有 Outcome、Behavior 判据两版均全通过，成绩变化集中在回复格式。系统提示与题面示例同时修改，本次对照不能区分两项修改各自的作用；相同模型别名也不保证提供方内部版本未变。

运行约 189 秒，195 次请求全部取得用量：输入 295,273 tokens，输出 13,646 tokens；实际费用以账单为准。已验证每版 65 个报告/日志引用，共 130 个，并从原始试验重新计算汇总。10 次多轮试验各自保持同一个 Session 和两个独立 runId，其中 A5-02 的 7 次均观察到约定的压缩接续。

两版的模型配置、题目 ID、重复次数、风险等级、夹具、业务期望、判据、参考解和反例经对照一致；源码变化仅为 `src/agent/messages.ts`。旧版报告和成绩保留，新版没有剥离正文、放宽判据或覆盖旧报告。

用户验收确认与本次 API 授权分别保存在新版运行目录的 `user-acceptance.json`、`egress-authorization.json`。逐条双人评审台账尚未录入，所以机器报告保留其 `pending` 状态；会话中的确认没有被伪造成两位评审者的逐条记录。

当前 100% 只适用于 14 条公开 `gold_dev` 任务及其重复试验，不代表完整能力空间已覆盖。下一步应保留当前版本作为回归基线，优先补充高风险组合、边界输入和异常状态；每个新场景先定义业务规则、参考解及独立反例，再按源问题家族划分开发与留出集。新增样本完成校准和人工验收后，再运行模型评测，避免只改写现有题面来增加数量。

首批扩展见[金种子受控变异 v1](evaluation-mutations.md)：20 条派生候选来自 10 个既有家族，包含边界、审批拒绝、对抗与三轮对话。扩展包单独构建和校准，父版本和本页历史模型成绩保持冻结。[2026-10-03 真实模型验证](evaluation-mutation-baseline.md)已完成 108 次试验，104 通过、4 失败、0 排除，变体宏平均 pass@1 为 97.1%。失败集中在 3 条对抗变体的任务结果；现有行为与回复格式判据均通过。该实验属于公开开发集验证，逐条人工评审台账状态单独保留。

随后按第 6–8 节的去重、规则、可解性、分布、重置与分层 Oracle 要求，构建了 [150 条变体 v2](evaluation-expansion-150.md)。本包保留原 20 条并新增 130 条；[本地验收结果](evaluation-expansion-150-results.md)与上述历史模型成绩分别记录。
