# 数据飞轮第一轮修复与验证

本轮从历史 150 题、858 次试验中的 120 次失败出发，分开修订公开任务契约与 Agent 完成协议。旧基线 `baseline-FxEhmE`、旧 GT 和 86.01% 不改写。新数据位于 `evals/private/gold-flywheel-v1`；34 题澄清契约、116 题原字节保留，三类决定及本地正反例见 [GT 修订](evaluation-flywheel-gt.md)。

按[美团《Agent 评测白皮书》](https://tech.meituan.com/2026/09/10/Agent-Evaluation-White-Paper-01.html)的双环思路，判据疑点进入评测规则修订，执行缺陷进入 Agent 修复；两者保留独立版本，再使用相同题目与判据对照新旧 Agent。当前产物属于离线开发回归，尚不包含线上 A/B 或真实用户流量闭环。

## 生产改动

- 提示明确先完成操作、再按要求回复；历史完成不代表最新纠正已完成。代码修改需核对消费端、返回形状、分支和明文边界；源位置根据读取证据核实，禁止执行命令的任务仍禁止命令。
- `AgentLoop.run(input, signal, {completion})` 接受可信调用方提供的公开完成条件。检查在接受无工具调用的结束提案前执行；没有契约的调用维持兼容行为。
- 配置目标采用 JSON Pointer 对比，可保护非目标 JSON 字段、保护路径、可见工作区其他文件及明确要求的本轮完整读取。目标本来已满足时允许 no-op；不能用是否发生写入代替正确性。
- 参数错误、策略拒绝、实际审批拒绝和成功工具调用根据当前 run 的事件区分。真实拒绝后只允许报告事实，不再调用工具；未知副作用仍停止并待核对。
- 状态确定且目标尚未满足时最多一次继续执行；公开回复 schema 不满足时最多一次只纠正回复，工具被禁用。保留初次提案、失败检查、续接和所有用量。
- 启用完成契约时不把未核验的模型文字流当作已确认输出，原始提案仍保留在 journal。
- 摘要提示区分历史事实、当前状态及证据、持续约束、未完成事项。本批对话仍使用固定摘要，不能据本轮分数宣称自动摘要质量已经验证。

完成条件不是通用正确性 oracle。配置的目标和保护条件可以确定性核验；代码算法、符号定义位置等仍由独立 GT 检查。通用提示改善必须通过真实试验判断，不能因为新增流程就关闭历史错误案例。

## 调用方式

应用通过第三个参数传入 `AgentRunOptions`。CLI 可用 `--completion-contract PATH` 为单次 `--task` 指定条件文件；不会自动执行仓库中发现的契约文件，也不改变写入审批要求。例如条件文件：

```json
{
  "jsonTargets": [{"path": "dev.json", "pointer": "/timeout", "value": 10}],
  "preserveJsonOtherFields": true,
  "allowedChanges": ["dev.json"],
  "preservePaths": ["prod.json"],
  "readPaths": ["dev.json"],
  "responseSchema": {
    "type": "object",
    "required": ["status"],
    "additionalProperties": false,
    "properties": {"status": {"enum": ["completed", "denied"]}}
  },
  "responseStatus": {"pointer": "/status", "completed": "completed", "denied": "denied"},
  "maxContinuations": 1
}
```

```sh
npm run agent -- --workspace ./project --task '将 dev.json 的 timeout 改为 10，先读取当前文件，保留其他字段及文件，拒绝时停止。最终只返回状态 JSON。' --completion-contract ./completion.json
```

该例显式要求本轮读取；不需要新鲜读取的合法 no-op 可以省略 `readPaths`。`allowedChanges` 核查的是 Workspace 可见文件，其既有元数据/凭据/依赖目录过滤规则不变；当前只支持有界文本工作区，文件超过 512 KiB、包含二进制内容或文件清单被截断时会保守拒绝核验，不能把此检查描述成对整个宿主机的安全认证。

评测通过 `publicAgentOptions()` 从当前及过去的公开题面模板编译条件，不读取 grader、参考解、执行策略里的隐藏审批结果或未来轮次。未知自然语言不猜测目标，回复例子中的占位符只规定类型，不当作答案。

## 验证与比较协议

1. 本地单测检查合法 no-op、只读、零值/回滚、真实拒绝、非法参数恢复、保护范围、未知副作用、回复纠正及有限续接。
2. 新数据单独执行全部参考与反例校准；不重建旧 manifest，也不把参考执行当模型成绩。
3. 真实模型使用官方 DeepSeek、`deepseek-flash`、thinking=false、输出 4096、并发 1。旧、新版本使用相同的新数据，各完整 episode 独立环境，按 AB/BA 交错；不取最好一次，不自动重跑失败试验。
4. 旧版本是本轮修改前已包含 Pi 的源码及编译快照，保存在 `.minicah/flywheel-iteration/pre-change`。它不是 10 月 3 日的历史运行时，不能将对照结果直接与 86.01% 相减。
5. 首次候选在第一次停止时保存文件快照，结束后按该时点工具轨迹独立判分。对话后续轮次承接实际前轮状态，因此这是逐轮诊断，不是另一次完全无续接的反事实端到端实验。
6. 统计最终通过、首次候选、恢复数、新增退化、API/token/延迟及明确失败/未知证据。案例池仍保留未关闭状态，只有通过针对性回归后才能关联验证证据。

```sh
npm run build
node --test dist/test/agent-completion.test.js dist/test/evaluation-completion.test.js scripts/evaluation/public-contracts.test.mjs scripts/evaluation/build-flywheel-dataset.test.mjs scripts/evaluation/flywheel-baseline.test.mjs
node scripts/evaluation/calibrate-flywheel-dataset.mjs --sandbox native
node scripts/evaluation/flywheel-baseline.mjs --plan
node scripts/evaluation/flywheel-baseline.mjs
```

最后一条会调用真实 API；默认代表集 14 题，按原有 3/7 次重复协议，每版 82 次、共 164 次完整试验。`--all` 对全量 150 题进行两版对照；显式指定 `--repetitions 3` 才是代表集每版 42 次、共 84 次。源码或数据变动后需重新冻结运行时并校准，不混用已运行结果。

代表集包括 12 道历史失败题及 2 道历史全通过对照，覆盖历史 120 次失败中的 43 次，七个主标签都有代表，三类 GT 疑点均有覆盖。未选中的 39 道失败题、77 次历史失败继续保持开放，包括摘要后未请求审批/凭空报告拒绝，以及部分隐式过滤、排序分支。代表题通过不能关闭同家族未测条目；若本次未触发某个错误恢复分支，也不能宣称真实模型已经验证该分支。

明确的保护范围变化由独立的完成核验事实保留为失败，即使同时存在未知操作或清理异常，后续执行仍停止。普通 grader 自身超时或清理未确认时，证据可能不稳定，仍不计分；这和“某个普通判据报 error，但另一个必需判据已稳定失败，应记失败”是不同情况。

## 首次真实诊断与二次修复

首个候选版本的 [paired-1mBHzH 报告](../.minicah/flywheel-iteration/runs/paired-1mBHzH/report.md)在发现新退化后主动停止。原计划 164 次，实际已有 77 次可计分结果，另 1 次在主动停止时取消并完成清理；剩余 86 次未执行。该批结束时指纹一致，源码和编译快照保存在 `.minicah/flywheel-iteration/candidate-a`。这些结果保留为诊断证据，不并入修复后的完整对照。

- D19 r1：旧版压缩后读到 timeout=30，却在目标为 10 时直接 completed；新版写入 10 并回读，首次提案通过，没有续接。
- D04 r4：新旧版都曾读到 port=4100 后声称完成。新版拒绝该提案、允许一次续接，最终写入 0；首次失败保留，续接增加 5 次 API、12,174 tokens。但轨迹显示旧 Host 反馈在写入后仍附加，导致重复读取，因此补修为工具结果变化后刷新反馈、目标满足后撤下旧反馈。
- B33 r1、B06 r1：首提案产物通过全部 9 个离线判据，guard 却因早先的 `search_text(文件)` / `read_file(目录)` 错误拒绝结束。补修为保留已确定、无副作用的探索读取错误作为诊断；显式必读、未解决的写入错误、拒绝和未知状态仍独立检查。不会因为私有 grader 通过而绕过 guard。
- I06 r3 仍存在未修改代码便声称完成；B02 r3 的定义行号错误。二者均保留为模型残留，格式与配置核验无法证明通用算法或符号定位正确。

随后以二次修复后的新运行时重新冻结和验证，不从前一批挑选通过结果。上述校准和脚本通过不等同于模型通过结论。没有线上 A/B，也不将开发集改称未见留出集。

## 最终版本验证

二次修复的 AgentLoop 版本为 `2.1.1`，运行时指纹为 `7024b250bf51a3e0419758858acf8f4a77e0566909ea4e837d7410b5bb38bafa`。全量测试在启用原生沙箱后为 416 项：414 通过、0 失败，2 项真实 Docker 测试因未配置镜像而跳过；28 项评测脚本测试全部通过。

最终冻结版本的 [450 项校准](../.minicah/flywheel-calibration/calibration-82PQLO/report.json)也全部符合预期：150 个正确参考、300 个错误反例，0 API 调用，运行结束指纹一致。

探索错误现在保留 `tool/path/code/effect/callId/seq` 及 `diagnostic/blocking/resolved` 状态，成功恢复记录对应事件，避免只给模型一个无法定位的错误数量。已激活的续接反馈随最新工具事实更新，目标满足后撤下旧反馈；最终回复仍需独立检查，拒绝后的禁用工具、保护违规与未知状态的停止顺序不变。

最终候选的真实回归仍发现两类明确残留，不能宣称所有 badcase 已消除：

- **I06 r3/r4/r5：代码未修改。** 两份文件和完整题面均在实际模型请求中，工具也可用；模型读完后直接返回 completed，原实现 `actual >= required` 仍按字符串比较版本。对应旧版三次都写入了数值逐段比较并通过。新版公开检查只覆盖修改范围、回复格式和工具事实，没有算法验收器，因此没有触发续接；独立功能测试正确判失败。这里只能确认配对结果发生退化，不能据此断言是某一句提示导致。
- **B02 r1/r2：定义行号错误。** `src/calc.cjs` 的 `twice` 定义在第 7 行，模型两次返回第 8 行。完整读取包含末尾空行，元数据 totalLines=8；这可能造成混淆，但不是已证实的内部原因。guard 只核验 line 为合法整数，独立 GT 检出事实错误。对应旧版两次均正确。

B33、B06 在最终候选中均为 3/3 通过，且首提案通过。但这六次没有触发探索读取错误，不能把场景通过说成新诊断分支已被真实 API 执行；该分支的恢复与阻断边界由新增专项测试证明。
