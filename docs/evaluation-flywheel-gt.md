# 失败反馈驱动的评测契约修订

`gold-flywheel-v1@1.0.0` 从冻结的 `gold-mutations-v2@2.0.0` 派生，仍为 150 条公开开发集变体、10 个已曝光父家族，未增加独立种子或留出集。它把三类已发现的题面歧义明确为业务契约，不回改历史分数，也不声称 Agent 已修复全部失败。

## 本版业务决定

| 疑点 | 新版本公开要求 | 覆盖范围 |
| --- | --- | --- |
| 是否递归迁移 retries | 仅迁移每个 JSON 文件根对象上的 retries；嵌套对象和数组原样保留 | GS-A2-02 家族 6 题 |
| 目标已满足时是否重读 | 每轮请求都先核实当前状态；合法 no-op 可以不写，但不能跳过本轮读取 | GS-A5-01、GS-A5-02 两家族 28 题的每一轮 |
| search_text 是否等价于读取 | 这些配置任务明确需要 read_file 的当前完整内容及 hash；搜索命中和历史摘要不能代替本轮快照 | 上述 34 题；只读准备轮明确读取 dev.json 和 prod.json，后续轮只要求目标 dev.json |

34 条题目更新题面及其 contract 来源；116 条题目逐字保留。所有题目的初始文件、隐藏测试、graders、参考解、原有反例、权限范围、模型工具、重复次数均保持不变。固定摘要仅补充首轮已声明的持续读取规则，不加入未来用户目标或隐藏期望值。新要求可能影响模型行为，因此本版与旧版得分不能直接相减并归因于 Harness 修复。

这些决定是新版本的明确产品要求，并不证明旧版对 GM-B17、GM-D10、GM-D23、GM-D28 的 17 次争议判分已经正确或错误。旧版人工裁决保持 pending；本版逐题人审也保持 pending。机器校准证明判据可运行，不能代替人工审阅。

## 数据与证据

- [新数据索引](../evals/private/gold-flywheel-v1/index.json)：保留 GM-* 编号，同时记录新旧内容哈希。
- [契约变更记录](../evals/private/gold-flywheel-v1/contract-decisions.json)：逐题、逐轮提示哈希及修订依据。
- [失败案例池](../evals/private/gold-flywheel-v1/case-pool.json)：历史 120 次失败、51 条题目，以及这些题目已有的 197 次唯一成功对照引用。
- [人审账本](../evals/private/gold-flywheel-v1/human-reviews.json)：默认空账本，构建不会覆盖已有人工记录。

案例池区分观察、因果归因、候选修复、实现版本、首次/最终复测结果、关闭状态。实际原因未经验证时 `causalClaim` 为 null；没有同题成功执行时明确记录缺失，不能伪造成功对照。初始化状态统一为 `open / not-run`，不能因为提出修复或改过题面就关闭。后续实验使用新报告补充证据，保留这份构建时快照。

历史报告仍为 858 次试验、738 次通过、120 次失败，通过率 86.01%。报告 SHA-256 为 `38f93b90fe8d12cae304a7adfb6a9691aab78cbe7fc3c7bc41348f1c469a2153`，构建时校验。构建还校验旧数据 manifest 中所有文件，再复制继承的三个测试包，不依赖当前运行时代码匹配旧版 runtime hash。

新 manifest 绑定本版数据、构建脚本和本文。运行时代码、模型与 thinking 配置、工具权限及环境应另外绑定到每一份实验报告。这样数据审阅与代码修复分别留痕，不会因为无关运行时代码变化而伪称数据人审已经失效或通过。

## 本地构建与校准

```sh
npm run build
node --test scripts/evaluation/build-flywheel-dataset.test.mjs
node scripts/evaluation/build-flywheel-dataset.mjs
```

测试使用本地确定性参考程序，不调用模型 API。除了验证 150 题数据保留与来源绑定，还实际执行以下正反例：

1. GM-B17 正确顶层迁移通过；递归改动 child.retries 只让对应结果判据失败。
2. GM-D10、GM-D23 目标已满足时，当前完整读取通过；直接报告完成只让读取判据失败，结果判据保持通过。
3. GM-D28 首轮 read_file 完整快照通过；仅搜索得到两份单行 JSON 后报告 ready，让两个显式读取判据失败，后续轮可继续通过。

相同输入可重复构建；已有生成文件内容不同则拒绝覆盖。不要在冻结输出目录中修改题目后重建覆盖，应发布新版本。历史分数、人审、运行记录均不因构建而重算。

## 修复验证边界

在本版上验证 Harness 收益，应同期交错运行旧行为和新行为，固定本版题面、GT、模型、thinking、工具与重复协议，分开统计首次通过率、续接后通过率、额外请求/tokens/延迟及原成功题退化。题面修订本身的影响应另做固定 Harness 的旧/新版数据实验。

本版仍是已曝光开发集，局部正反例校准以及代表题 API 复测均不能替代 150 题全量回归，更不能宣称独立泛化成绩。参数错误、真实拒绝、未知写入状态、合法 no-op、只读任务须保留为回归边界；实际拒绝后不能以自动重试追求通过率。
